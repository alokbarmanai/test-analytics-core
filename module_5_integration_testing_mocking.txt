Core Concepts to Understand
The Schema Model: A standard Python class inheriting from a base database declaration. Every attribute you define on this class becomes a structural column inside your relational table.
The Database Engine: The underlying connectivity pipeline. For lightweight projects and automation frameworks, we use SQLite, an in-process, file-based SQL database engine that saves your whole database directly as a single local file (e.g., test_analytics.db).
The Session Context: The transaction wrapper. A database session acts like an open notepad. You can add multiple rows or update fields, but nothing becomes permanent until you issue a .commit() command.

Core Concept: How the yield Keyword Automatically Manages Teardown
Notice how your test fixture was written:
@pytest.fixture(scope="function")
def db_session():
    # Phase 1: Setup Code
    init_db()
    session = SessionLocal()
    
    yield session  # <-- The Pause Button
    
    # Phase 2: Teardown Code
    session.close()
    Base.metadata.drop_all(bind=engine)

READ AGAIN-Very Important Information:
In your 12 years of Java experience, you handled this using separate methods annotated with @BeforeMethod and @AfterMethod (TestNG/JUnit). In Python, pytest handles this with a single function using a generator wrapper (yield):
1. The Setup: Pytest runs everything before the yield keyword first (creating tables and opening the database connection).
2. The Execution: As soon as it hits yield session, pytest pauses execution of the fixture, hands the live session object over to your test function, and executes the test (test_persist_and_read_health_record).
3. The Teardown: Once your test finishes (whether it passes or completely crashes), pytest automatically returns to the fixture and runs everything after the yield keyword inside the finally block, closing the connection and dropping the tables to ensure data isolation.
